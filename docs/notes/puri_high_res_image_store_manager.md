# プリの高画質画像保持マネージャー  
  
## 前提  
ウェブアプリのプリで、ユーザーが撮影した写真をOOMを引き起こさずに保持するのが目的。  
通常のウェブアプリと、そのウェブアプリにブラウザだけじゃできない一眼レフのPTP制御やOSのプリンターの印刷機能を叩くNode.jsを連携させて改造したブース版のウェブアプリでほとんどの処理(Node.jsに関わるところ以外)が共通。  
スマホのカメラ写真かもしれないし、WebSocketでNode.jsから来た一眼レフの写真かもしれない。  
実際に動かす環境はスマホかもしれないし、iPadかもしれない。  
このメモではユーザーは開発者を指す。  
このメモではキャンバスはオフスクリーンキャンバスを指す。  
  
## フロー(ユーザーから見て)  
- 対象の画像をマネージャーに追加して後は画像の参照を断ち切る  
- 使うときだけマネージャーから画像受け取る(取得メソッドにはImageBitmap(内部的にはFileからキャンバス介さず直行)、HTMLImageElement(内部的にはcreateObjectURLでURL生成と、onload時にrevokeしてる)など複数の型用のメソッドが用意されている)  

## 独自の画像クラス  
- ユーザーがマネージャーなしで画像を扱うような使い心地にするため、クラスのラッパーを用意する  
- マネージャーのクラスのメソッドから返される画像IDとかを自動でインスタンス内で保持して、ユーザーにインスタンスに画像が入ってるように錯覚させる(カプセル化)  
- JSの仕様でコンストラクタでawaitできないので、別に初期化メソッド用意  
- 初期化メソッドで裏側でマネージャーの追加メソッド叩いて、画像ID保持  
- removeメソッドでマネージャーの個別の削除メソッドを叩く(多分実務ではほぼ使われない)  
- FinalizationRegistryで参照切れたらremoveメソッドと同じ動作する  
  
## クラス(シングルトンとしてエクスポート)  
### コンストラクタ  
- ページアクセスごとに一時保存に使ったOPFSをクリーンにするため、一時画像フォルダの存在を確認して、存在すればフォルダごと削除する  
### 追加メソッド  
- 追加メソッドで画像が追加されたら即座にワーカーに移されて、メインスレッドはワーカーの処理が終わったら画像に割り当てられた画像ID(UUIDを想定)を返す  
- ワーカーで、キャンバスでロスレス(品質に1.0指定)でWebP変換して、OPFSに保存(ファイル名は画像ID、一時画像フォルダに入れる)  
### 取得メソッド  
- 指定された画像IDの画像をOPFSから引っ張る  
- 取得メソッドの用途の型に応じて変換(ものによっては変換もしない)  
- 返す  
### 明示的な初期化(clear)メソッド  
- OPFSの一時画像フォルダの存在を確認して、存在すればフォルダごと削除する  
### 個別の削除メソッド  
- 画像IDで指定した画像だけOPFSから消す
